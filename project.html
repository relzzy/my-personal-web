Code Intelligence & RAG

One of my main projects is a local code intelligence and RAG system built around a fine-tuned Qwen3.5-2B language model. The goal is to create a lightweight AI system that can understand a large codebase, retrieve the right information, and interact with the local Linux environment when needed.

The model itself is fine-tuned specifically for Linux-focused tool use and routing, rather than being used as a general-purpose chatbot. It learns to determine what the user is asking for and return a structured tool call that can be handled by the rest of the system.

How the system works

  • Fine-Tuned LLM Router — A 2B-parameter Qwen3.5 model fine-tuned using QLoRA and Unsloth. It classifies the user's intent and produces structured JSON tool calls. The training data is focused on Linux commands, system operations, codebase queries, and tool usage.
  • Codebase Retrieval — When a question requires understanding the project itself, the request is sent to the RAG pipeline rather than directly to the terminal.
  • Hybrid Search — The RAG system combines dense vector search using ChromaDB with BM25 keyword search. This allows it to find both semantically related code and exact matches such as function names, variables, filenames, and technical terms.
  • Reciprocal Rank Fusion — Results from the different search methods are combined using RRF (Reciprocal Rank Fusion), producing a stronger combined ranking instead of relying on a single search method.
  • Cross-Encoder Re-ranking — The most relevant results are then passed through a cross-encoder reranker to improve the final selection of context given to the language model.
  • Linux Tool Integration — System-level questions can be routed to controlled Linux tools for things such as file discovery, logs, processes, memory usage and system inspection.
  • Final Response — The retrieved code or system information is passed to an LLM to produce a grounded response based on the available evidence.

The system has been tested on a codebase containing 350+ files, successfully indexing and retrieving relevant information from across the project. The initial indexing is a one-time process, after which queries can use the existing search indexes instead of processing the entire codebase again.

The trained model can also be deployed locally using 4-bit GGUF quantization, making the system practical on consumer hardware while keeping the data and inference local.

Cue — Realtime Creator Video Review & Scheduling Engine

Cue is a multi-tenant creator review and scheduling platform engineered to streamline video drafts, carousel reviews, revision tracking, and client approvals. In agency and creator workflows, review rounds routinely degrade into lost Google Drive links, scattered WhatsApp threads, and timezone confusion across international clients. Cue solves this by replacing ad-hoc communication with isolated workspaces, dynamic timezone normalization, and sub-second feedback loops.

Rather than a passive showcase site, Cue runs as a fully reactive web platform powered by Next.js App Router, TypeScript, and Supabase, incorporating deterministic review state machines, database-enforced multi-tenancy, and live WebSocket synchronization.

System Architecture & Core Engineering

  • Universal Timezone Normalization Engine — To eliminate timezone errors when coordinating cross-continent social campaigns, all schedule timestamps are persisted to PostgreSQL in strict UTC ground truth. The frontend dynamically queries the user's runtime device clock using ECMAScript's native Intl.DateTimeFormat API, automatically rendering local publishing times alongside universal UTC indicators.
  • Multi-Tenant PostgreSQL Data Isolation — Tenant security is enforced at the database layer using PostgreSQL Row-Level Security (RLS) policies coupled with email whitelisting. Client organizations are sandboxed into dedicated workspaces with custom branding and logos, guaranteeing zero cross-tenant data leakage of drafts, feedback notes, or unreleased assets.
  • Workspace-Scoped Role-Based Access Control (RBAC) — Configured granular database permissions allowing a user to act with Creator permissions (uploading drafts, modifying slide orders, triggering resubmissions) in one workspace, while holding Reviewer permissions (issuing approvals and logging revision notes) in another.
  • 4-Way Review Decision State Machine — Implemented a deterministic approval pipeline featuring four explicit states: Approve, Suggest Changes, Put on Hold, and Deny. Guarded by form-level and schema-level validation requiring mandatory revision notes before review submission, followed by an atomic 1-click resubmission loop that resets updated drafts directly back to Pending Review.
  • Sub-Second Realtime Streams — Subscribed the client dashboard to Supabase Realtime WebSocket channels listening directly to PostgreSQL change data capture (CDC). Status updates, reviewer notes, and slide-out team chat messages synchronize across all active viewers with sub-second latency and zero manual page polling.
  • Multi-Format Media Review Canvas — Engineered specialized inspection flows for 4:5 portrait carousels (including slide navigation, safe-zone overlays, and visual hook frameworks), vertical short-form video (TikTok, Instagram Reels, YouTube Shorts), and external review embeds from Loom, Google Drive, Frame.io, and Figma.

Deployed on Vercel utilizing modern React Server Components and optimized edge streaming for fast first contentful paint.

AI-Driven Narrative RPG

One of my newer projects is a web-based RPG that combines traditional game systems with AI-generated content. Instead of allowing AI to completely control the story, the game uses a fixed canonical main storyline as its foundation while allowing AI to generate flexible dialogue and events around it.

  • AI-generated dialogue and procedural events that respond to the player's situation.
  • A persistent character, inventory and statistics system that keeps track of the player's state.
  • Player decisions and game state can affect future events and potential endings.
  • The AI operates within the game's existing rules instead of being allowed to freely rewrite the underlying game state.
  • The project is currently in beta and runs through a web interface.

Visual Novel / RPG Engine
